---
title: their own chatgpt plan
description: people connect chatgpt, and their requests run on their plan
---

okay so the annoying thing about letting other people change your app is that every change they make costs you money. this is the way around that: someone presses **Continue with ChatGPT** in the box, approves it over at openai, and from then on their requests are made by codex on their own chatgpt plan and not on anything you pay for

```js title="computah.config.mjs"
export default {
  // ...
  chatgpt: { require: "members" },
};
```

it's openai's [sign in with chatgpt](https://developers.openai.com/siwc), which is a real thing they built for other apps to use, not a trick with someone's codex login. the person sees exactly what they're allowing, they can cap how much of their plan this app gets or cut it off in their chatgpt settings, and it never gives the app their conversations

## the two ways openai offers it

| | what you need | how the sign-in comes back |
| --- | --- | --- |
| the open-source flow | nothing. each person registers a little client of their own the first time they sign in | to `127.0.0.1` on the person's own machine |
| a client id from openai | you ask for one with [this form](https://openai.com/form/sign-in-with-chatgpt-interest/) | straight to your app, at `https://your.app/__computah/chatgpt/callback` |

`chatgpt: {}` is the open-source flow, and it works in both of these situations:

- **the runner is on their machine** (your laptop). openai sends them back, the runner catches it, and they're connected without doing anything else
- **the runner is somewhere else** (a server). openai still sends them to `127.0.0.1`, which is their own computer, so they land on a page that won't load. the address of that page has everything in it, so the box asks them to copy it and paste it back, and that finishes it. it's the same thing codex's own cli does for signing in on a remote machine. the address only works once, only with a secret the runner kept, and only for the person who started it

one thing to be straight about: openai's docs describe the open-source flow as for "open-source and locally hosted apps" and point remotely hosted ones at that form. so whether to run the paste version on a public site, or wait for a client id, is between you and openai. computah does both:

```js
chatgpt: {
  clientId: process.env.OPENAI_CLIENT_ID,
  // only if openai gave you a confidential client
  clientSecret: process.env.OPENAI_CLIENT_SECRET,
  require: "members",
},
```

their requests use the first model openai lists for their own account, which is its current best (for mine that was `gpt-6.2-sol`), unless you set `chatgpt.model`

## who has to connect

| `require` | |
| --- | --- |
| left out | nobody has to. someone who connects runs on their plan, and everyone else is served by your agent like before |
| `"members"` | people who aren't owners or trusted have to connect before they can send anything. this is the one for a public app |
| `"everyone"` | you too |

someone who has to connect and hasn't gets "connect your chatgpt account first" and the button. if they connected and then disconnect (or cut the app off at openai), their next request doesn't quietly fall back to your agent, it tells them to connect again

## what the box shows

- **Continue with ChatGPT** when they can connect
- "You're using your ChatGPT plan" once, right after they do, which openai asks apps to confirm
- after that "Using ChatGPT plan", their email, **Manage usage** (which opens their chatgpt usage settings) and **disconnect**
- if they hit their plan's limit the request fails and says so, with where to check it

with your own box on [the hook](/styling) it's `box.chatgpt` (`connected`, `email`, `required`), `box.connectChatGPT()`, `box.disconnectChatGPT()`, and `box.chatgptJustConnected` with `box.dismissChatGPTWelcome()`. for the paste version, `box.chatgptPaste` turns true after `connectChatGPT()` opens the sign-in in another tab, and you hand the pasted address to `box.finishChatGPT(address)` (or `box.cancelChatGPT()`)

## what happens to their sign-in

this is the part to be careful about, since you're holding something that spends another person's plan

- **it stays on the runner.** each person's sign-in is a file under `.computah/chatgpt/` that only the runner's user can read. it never goes to their browser, into a url, or into a log
- **only their own requests use it.** the token is handed to codex in that one process's environment, never as an argument, and nobody else's request can pick it up
- **it's checked properly.** the sign-in uses pkce, a one-time `state`, and the id token's signature, issuer, audience, expiry and nonce are all verified against openai's published keys before anything is saved
- **disconnecting is real.** it ends the session at openai and deletes the tokens here. if openai doesn't confirm, the box says so and tells them they can remove the app in chatgpt's settings
- **with a [sandbox](/sandboxes),** the token goes into the sandbox for that one run, through stdin into a file that's deleted before codex starts. the sandbox has to be able to reach `api.openai.com`, so on exe that's `exeSandbox({ egress: "all" })`

requests run with `codex exec` pointed at a provider that sends their token, the way openai's docs set up codex for this, so `codex` has to be installed where the agent runs

## what's tested

i connected my own chatgpt account both ways. on my laptop the sign-in came straight back, and codex made a change on my plan in 28 seconds. on a server i did the paste version (from a train lol), and that one took 30 seconds. i also forced a renewal to check the token gets replaced properly, and it did

the refusals (forged, replayed and swapped answers) run in tests against a pretend openai that issues real signed tokens, checks pkce and burns each refresh token after one use

what i haven't been able to check: the flow with a real client id from openai, cause i don't have one. the scopes a partner client gets might differ from the open-source ones (there's a `scopes` option if so)
